懒猫微服比其他 NAS 好在哪里？

发表于2026-08-21|更新于2026-08-21|懒猫微服番外
|总字数:3.8k|阅读时长:11分钟

玩过不少 NAS，从最早的黑群晖、威联通，到后面的飞牛、绿联、极空间、UNRAID、ESXi 和 Proxmox VE，基本上该折腾的都折腾过。

最早知道懒猫微服的时候，我的第一反应其实不是“这东西真好”，而是价格比同类型 NAS 贵一些。小主机越来越便宜，自己装一个系统也不难，单看 CPU、内存和硬盘，有人觉得有溢价，甚至怀疑是不是割韭菜，我当时也有类似的疑问。

真正买回来重度使用之后，才发现用硬件参数去计算它的价格并不完整。就像买云服务器不能只算 CPU 和硬盘，懒猫里面还有网络服务、客户端、应用商店、账号系统、技术支持和后续维护。

每次写懒猫微服，总会有人问一个问题：

懒猫微服到底比其他 NAS 好在哪里？

这个问题不好回答，因为每个人对“好”的定义不一样。

如果只比较盘位、CPU、万兆网口和每 TB 存储成本，懒猫不一定占优势。自己组一台机器，安装飞牛或者 UNRAID，性价比可以做得很高；群晖和威联通在存储、备份、相册、监控这些传统 NAS 功能上也积累了很多年。

但如果把 NAS 当作一台需要长期使用、随时远程访问、可以运行各种应用的家庭服务器，懒猫的优势就会慢慢体现出来。

我自己的结论是：

传统 NAS 更擅长解决“文件放在哪里”，懒猫微服更想解决“这些数据和应用怎么被人随时使用”。

它卖的不只是一个装硬盘的盒子，而是一套从网络、账号、客户端、应用商店到技术服务的个人云环境。

远程访问不是懒猫独有，区别在于做得有多彻底

首先要说清楚，远程访问并不是懒猫独有。

群晖有 QuickConnect，可以不配置端口转发，通过 QuickConnect ID 访问 DSM、Drive、Photos 和 File Station 等官方套件；威联通也有 myQNAPcloud，可以使用 SmartURL 和中继服务远程访问 NAS。

所以如果只是从公司打开家里的文件，传统 NAS 也能做到，没必要为了这个功能单独换设备。

真正的区别，是安装第三方应用之后。

传统 NAS 上跑一个 Docker 服务，通常要处理这些东西：

  1. 容器映射哪个端口。
  2. 路由器是否需要端口转发。
  3. 域名怎么解析。
  4. HTTPS 证书怎么申请和续期。
  5. 反向代理应该怎么配置。
  6. 手机在外面访问时应该记哪个地址。

服务少的时候还好，服务多了以后，端口、域名和各种登录入口就开始失控了。

我家里虽然有公网 IP，但是运营商会不定时封端口。以前为了从外面连回家里，用过 DDNS、路由器端口转发、蒲公英异地组网、Cloudflare Tunnel，也常开过 Windows 跳板机。每一套方案单独看都能用，组合起来之后，就变成了只有自己敢维护的家庭网络。

后来换成懒猫微服，异地组网、应用访问和端口转发逐渐收进了同一套体系。Wiki、Memos、FreshRSS、清单和开发环境也可以从一个客户端打开。家里人不需要知道这些服务分别运行在哪台机器、哪个端口，只要点应用图标就行。

在我的实际使用里，商店应用安装完成后会得到统一的访问入口，不需要再为每个容器记住一个 IP 加端口。HTTPS、域名和远程访问不再是每个应用单独解决的问题，而是平台层统一处理。

这才是懒猫的优势：不是“有内网穿透”，而是把内网穿透变成所有应用都可以直接使用的基础设施。

客户端不只是用来寻找 NAS

传统 NAS 的桌面客户端，很多时候是用来寻找局域网设备、同步文件或者挂载磁盘。真正的用户管理、应用安装、系统监控和存储设置，最后还是要打开浏览器进入管理后台。

https://appstore.lazycat.cloud/#/shop/detail/cloud.lazycat.shell.files

懒猫的客户端更像一个统一门户。

登录客户端后，可以看到自己的微服、网盘和应用。设备管理、账号验证、成员邀请、应用入口和远程访问都放在同一套界面里。普通用户不需要先知道 NAS 的局域网 IP，也不用理解公网和内网的区别。

写这篇文章时，懒猫微服客户端下载页面提供 Windows、macOS、Linux、Android、iOS、鸿蒙、Server 和比亚迪车机等客户端。平台多不一定代表每个客户端都完美，但是至少可以看出来，它从产品设计之初就不是只考虑“电脑浏览器访问 NAS”这一种场景。

这对家庭用户很重要。

家里人不关心什么是 WebDAV、SMB、反向代理和容器端口。他们只关心打开 App 能不能看见照片，换一台设备能不能登录，出门以后还能不能使用。

专业用户喜欢配置，普通用户只想使用。一个家庭设备最后能不能长期运行，往往取决于普通用户觉得它麻不麻烦。

它把 Docker 服务做成了真正的应用

群晖有套件中心，威联通有 App Center，飞牛、绿联等国产 NAS 也都在快速补充自己的应用生态，所以应用商店本身也不是懒猫独有。

懒猫比较特别的地方，是把大量开源 Docker 项目重新打包成了 LPK 应用。

普通 Docker Compose 项目通常只有开发者才看得懂：

普通用户看到这里，可能已经开始找安装教程了。

而一个移植完成的懒猫应用，用户看到的是名称、图标、介绍和安装按钮。端口、数据目录、路由、权限和镜像都由应用包提前处理。

写本文时，懒猫官网首页标注应用商店已经超过 4289 款应用。数量当然不等于质量，有些应用可能比较小众，社区应用也会遇到上游停止维护、镜像版本落后等问题。但是这种生态至少解决了一件事：很多原本只存在于 GitHub README 和 Docker Compose 里的项目，变成了普通用户可以直接安装的应用。

对于开发者来说，还可以把自己写的软件或者喜欢的开源项目移植进商店。我自己上架过原创应用，也移植过纯前端工具和 Docker 项目。开发者写好一次，后面的用户就不需要每个人重新研究一遍 Compose。

这和传统 NAS 上“大家按照同一篇教程各自部署一个容器”是两种完全不同的生态。

多用户不是多建几个共享文件夹

NAS 放在家里，最后一定会遇到多用户问题。

传统做法一般是新建账号、分配共享文件夹权限，然后告诉家里人哪些目录可以访问。文件权限做得很成熟，但是到了第三方应用，每个应用可能又有自己的一套账号和密码。

懒猫把账号、设备和应用权限放到了一起。

管理员邀请家庭成员后，可以设置这个成员能看到哪些应用。每个人的网盘、清单和私有数据可以相互隔离，普通成员也不需要看到几十个只有管理员才会使用的工具。

新设备登录时还有安全码验证，设备也可以从管理界面注销。对于不懂技术的家人来说，这种体验更接近手机和云服务，而不是在使用一台服务器。

传统 NAS 当然也能做细粒度权限控制，企业型号甚至更强。懒猫的优势不是权限功能一定更多，而是把这些能力做成了家庭用户比较容易理解的操作。

对普通用户简单，对开发者又没有完全封死

很多面向小白的 NAS，为了降低使用难度，会把底层系统封得比较严。这样做有好处，用户不容易把系统玩坏；坏处是专业用户想做点官方没有提供的事情时，马上遇到边界。

懒猫比较符合我的地方，是它同时保留了两种使用方式。

普通用户可以只使用客户端和应用商店，像使用网盘和 SaaS 一样使用它；开发者则可以继续研究 Debian、Docker、虚拟机、网络、OIDC 和 LPK 应用。

我买回来以后，既用它给家里人共享网盘和清单，也拿来跑开发环境、Docker 服务和虚拟机，还写过一系列应用移植和排查文章。

这也是我一直说的：

普通用户图一个方便，专业用户图一个折腾。

很多产品只能满足其中一边。要么非常简单，但是能做的事情有限；要么自由度很高，但是从安装开始就需要用户自己维护。懒猫试图把两边放在一台设备里。

当然，这种设计也会带来复杂度。商店应用、Playground Docker、虚拟机和底层系统并不是一套东西，新用户刚开始可能分不清。对于职业习惯比较重的人来说，还会忍不住研究每个服务到底运行在哪里。

不过这属于“可以不用懂，但想懂还能继续往下挖”，比完全没有入口要舒服很多。

真正拉开差距的，可能是技术服务和社区

硬件参数很容易比较，技术服务很难写进参数表。

买之前朋友跟我说懒猫售后很好，情绪价值一定给拉满。我当时将信将疑，毕竟很多产品售前什么都能解决，付完钱就让你去看文档。后来真的开始问 Docker、Cloudflare、OIDC 和第三方应用问题，才发现这群人确实愿意跟着用户一起往下排查。

我以前使用其他 NAS 时，遇到产品本身的问题可以找售后；但如果问题同时涉及 Docker、Cloudflare、第三方开源项目和家庭网络，就很容易出现一个经典回答：

这是第三方软件的问题，请联系软件开发者。

这句话不能说错。厂商确实没有义务维护互联网上所有开源项目。

但是对用户来说，问题仍然没有解决。

懒猫给我印象比较深的地方，就是技术人员愿意继续往下排查。商店应用有问题，他们可能会联系应用移植者；网络和域名有问题，也会一起查看具体环境。社区里还有不少开发者长期分享 Docker、Linux、网络和应用移植经验。

我自己的很多文章，就是在问技术、看日志、反复测试之后整理出来的。

所以懒猫价格里包含的，不只是 CPU、内存和硬盘盒，还包括一套持续维护的软件系统、网络服务、应用商店和技术支持。

这也解释了为什么单看硬件参数，会觉得它有溢价；真正使用一段时间后，又会发现这个价格不能只按小主机加硬盘来计算。

懒猫并不是所有地方都比传统 NAS 好

说了这么多优点，还是要泼一点冷水。

如果你的主要需求是大容量存储、多个硬盘位、成熟 RAID、万兆网络、企业备份和监控录像，传统 NAS 厂商仍然很有优势。

群晖的软件成熟度、备份体系和照片管理积累了很多年；威联通的硬件扩展、接口和型号选择非常丰富；DIY、UNRAID、TrueNAS、飞牛的自由度和性价比也很有吸引力。

懒猫也有自己的问题：

  • 硬件选择和盘位没有传统 NAS 那么丰富。
  • 一部分远程体验依赖厂商提供的网络基础设施。
  • 社区应用数量很多，但质量和维护状态并不完全一致。
  • LPK 是自己的应用格式，生态规模还需要时间积累。
  • 对只需要局域网存文件的人来说，很多能力可能用不上。
  • 单纯按照硬件参数比较，价格不算便宜。

所以“懒猫比其他 NAS 好”并不是一个绝对结论。

更准确地说，它在下面这些场景里更有优势：

  1. 经常需要从外网访问家里的应用和文件。
  2. 不想自己维护 DDNS、端口转发、证书和反向代理。
  3. 家里有多个用户，希望账号、设备和应用统一管理。
  4. 喜欢安装各种开源软件，但不想每次都研究 Docker Compose。
  5. 既希望家人容易使用，自己又保留 Linux 和 Docker 的折腾空间。
  6. 遇到问题时，希望能找到真正懂技术的人继续排查。

如果只是需要一个便宜、稳定、盘位多的存储设备，那么传统 NAS 或 DIY 方案可能更加合适。

总结

懒猫微服比其他 NAS 好在哪里？

不是因为它发明了远程访问，不是因为只有它有应用商店，也不是因为它在所有硬件参数上都更强。

它真正做得比较好的，是把原本分散的事情串了起来：

  • 网络层负责远程连接。
  • 客户端负责设备和账号入口。
  • 应用商店负责软件分发。
  • 账号系统负责成员和权限。
  • LPK 负责把 Docker 项目变成可以安装的应用。
  • 社区和技术支持负责解决最后那些文档里没有写的问题。

传统 NAS 经常是买回来以后，再由用户自己拼 DDNS、Docker、反向代理、证书、账号和各种客户端。懒猫则希望把这套东西提前做好，让普通用户像使用云服务一样使用家里的设备。

它不一定是最便宜的 NAS，也不一定是最强的存储服务器。

但是对于想把数据放在自己家里，又不想每天做服务器运维的人来说，它确实是一条很不一样的路线。

这也是我最后留下懒猫微服、逐渐拆掉原来那套复杂家庭网络的原因：

技术当然可以折腾，但折腾应该带来新的玩法，而不是每天重复维护基础设施。
