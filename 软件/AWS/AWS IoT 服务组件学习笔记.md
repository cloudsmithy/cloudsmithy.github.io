我们要讨论的第一个组件是设备 SDK。 您的连接设备需要进行编码，以便它们可以与平台连接并执行操作。 Amazon Device SDK 是一个软件开发套件，其中包括一组用于连接、身份验证和交换消息的客户端库。 SDK 提供多种流行语言版本，例如 C、Node.js、Java、Python、Arduino 以及适用于 Android 和 iOS 的移动 SDK。 这些工具使编写代码并轻松连接服务变得相当容易。

接下来，您需要将设备安全地连接到平台。 身份验证和授权内置于 AWS IoT 服务中。 对象通过使用传输层安全性或使用相互身份验证的 TLS 版本 1.2 进行安全连接。 这意味着 AWS IoT 能够识别哪些设备已连接，并验证它不是冒充您设备的其他设备，然后设备还可以验证它们正在连接到 AWS IoT，而不是冒充该平台的其他实体。 您可以提供自己的证书，或者 AWS 有一个证书存储，您可以在其中请求证书来识别和保护您的设备，以便与 AWS 进行通信。 设备经过身份验证并连接后，您可以使用 IAM 规则和策略来精细控制设备可以执行的操作以及用户对设备生成的信息的访问类型。

我们来谈谈设备网关组件。 设备网关是一个消息代理。 它支持 MQTT、HTTP 和 WebSockets 等标准协议。 它用于在您的设备和 AWS IoT 之间交换数据消息。 这些协议使用标准的发布者-订阅者或发布/订阅模型。 因此，您的设备将使用适当的协议进行连接并以主题的形式发布数据。 应用程序将订阅该主题，并收到与其订阅主题相关的任何已发布数据的通知。 因此，例如，建筑物中的空调机组可能会发布有关建筑物内温度变化的信息。 然后，技术人员在手机上安装了该应用程序以帮助他监控这些设备，他将通过该应用程序在手机上接收温度消息作为信息。

连接到 Amazon IoT 服务的设备由注册表中的内容表示。 注册表用于为您的设备建立身份，并可以保存有关您的设备的数据、存储设备属性并跟踪设备。 AWS IoT 规则引擎提供消息处理、转换以及与其他 AWS 服务的集成。 它使用基于 SQL 的语言从消息负载中选择数据、处理数据并将数据发送到其他 Amazon 服务，例如 S3、Lambda、DynamoDB 等。

设备影子是物理事物或设备的虚拟表示。 设备影子的目的是，与您的设备不同，设备可能会休眠以节省电池电量或根据从人或应用程序收到的命令更改状态，设备影子始终可供您的应用程序使用，因此设备将报告其当前状态 到设备影子。 影子将根据从应用程序接收到的信息确定当前状态是否是所需状态。 如果所需状态与当前状态匹配，则影子将其状态设置为与物理设备的实际状态匹配，并且不会发生任何变化。 如果它们不匹配，则影子将向应用程序报告差异。 应用程序将设置所需的状态，并且影子将请求设备更改为所需的状态。 完成此操作后，设备和影子将同步。

例如，您关掉汽车并锁上车门，从后备箱取出杂货，然后意识到您已将钥匙锁在后备箱中。 您联系您的车载服务提供商并告诉他们您需要解锁后备箱才能拿到钥匙。 行李箱当前状态为锁定。 所需状态已解锁。 代理使用应用程序将状态从锁定更改为解锁。 后备箱打开，您可以拿到钥匙。
