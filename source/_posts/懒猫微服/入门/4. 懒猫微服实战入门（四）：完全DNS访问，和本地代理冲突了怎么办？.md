刚拿到懒猫微服时，了解到这台机器完全通过 DNS 访问，我很吃惊。根据不完全的使用经验，机器里大概部署了一套私有 DNS 服务，并把解析信息广播到整个局域网。公网使用的则是 heiyu.space；通过 WHOIS 查看，这个域名是在腾讯云购买的。

![image-20250513092022572](https://raw.githubusercontent.com/cloudsmithy/picgo-imh/master/image-20250513092022572.png)

所以这里应该有两套解析结构：在局域网访问时，优先使用机器部署的私有域名解析；使用蜂窝网络或者人在外面时，则走互联网上 DNSPod 的解析记录。这个结论属于猜测，因为很多公有云也会这样设计：一个公开托管域名用于互联网解析，一个 VPC 内的私有域名用于解析内部地址。

懒猫微服和传统 NAS 有很大不同。普通玩家可以很快上手，把它当作 SaaS 服务来用；但对于专业玩家，总有一种技术上的强迫症，想抽丝剥茧地从 SaaS 一路拆到 PaaS 和 IaaS，弄清楚懒猫如何把私有服务安全地提供给远程客户端。

比如网络，可以通过 `dig` 或 `nslookup` 查看解析结果：

```
dig xxx.heiyu.space +short
dig xxx.heiyu.space AAAA +short
```

但是，DNS 解析慢慢出现了问题。某次向懒猫网盘上传文件时，我发现速度慢得可怜，几乎像是走了公网。在 VIP 答疑群里得知，流量可能从代理绕了一圈再回来，所以才会变慢，接下来就是解决这个问题。

办法就是配置直连白名单，不让这些域名走代理。由于懒猫微服通过域名访问，而很多代理规则也是按域名匹配，所以需要修改对应规则。当然，如果你用 `nmtui` 配置静态 IP 地址，内网访问也可以直接走上级路由的默认路由表。

![image-20250513094205439](https://raw.githubusercontent.com/cloudsmithy/picgo-imh/master/image-20250513094205439.png)

白名单主要放行 `*.heiyu.space` 和 `*.lazycat.cloud`：heiyu.space 用于穿透服务，lazycat.cloud 用于官网和论坛。

不同软件的设置方式不同。使用 `DOMAIN-SUFFIX` 时，只填写 `heiyu.space` 这样的域名后缀即可。我一开始写成 `*.heiyu.space`，结果始终不生效，花了不少时间；实际上不需要再写 `*`。

![image.png](https://dl.playground.lazycat.cloud/guidelines/459/9ed1bbce-73b0-4ce9-8e22-fb20d6c8b21c.png)

最终落到配置文件上就是这样。（之前写成 `DOMAIN-SUFFIX,*.lazycat.cloud,DIRECT`，一直不生效。）

```
rules:
- DOMAIN-SUFFIX,lazycat.cloud,DIRECT
- DOMAIN-SUFFIX,heiyu.space,DIRECT
- DOMAIN-SUFFIX,deepseek.com,DIRECT
```

也总结一下其他规则吧，最常见的类型有这些：

### 1）DOMAIN

- 只匹配**某个域名本身**。
- 举例：`gs.apple.com` → 只有访问 `gs.apple.com` 才会命中。

### 2）DOMAIN-SUFFIX

- 匹配**所有以这个后缀结尾的域名**。
- 举例：`apple.com` → `gs.apple.com`、`itunes.apple.com` 都会命中。

### 3）DOMAIN-KEYWORD

- 匹配**包含某个关键词的所有域名**。
- 举例：`apple` → `apple.com`、`gs.apple.com`、`appleabc.xyz` 都会命中。

### 4）IP-CIDR

- 匹配**某个 IP 地址段**。
- 举例：`192.168.0.0/16` → 匹配 192.168 开头的所有 IP。

> 这些是规则写法里最基本的几种，掌握了就能应对绝大多数情况。
